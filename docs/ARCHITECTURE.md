# yun-laya 处理流程

```text
微信窗口（前台）
  └─ 窗口抓图 + 本地 Vision OCR
       └─ 确认对方的最新文字 + 最近对话
            └─ 本地 Laya：意图、风险、下一步
                 ├─ 暂不回复 / 用户自己处理 → 不调用回复模型
                 ├─ 本地模板 → 高情商、阴阳怪气、一本正经各一条
                 └─ 需要写句子 → 回复模型调用 1 次，三类各写一条
                                  └─ 本地 Laya 排序 → 悬浮窗 → 用户手动发送
```

`src/perception.py` 抽取可见消息与方向；`src/hud.py` 管理消息停稳、前台和会话切换、原生悬浮窗及过期结果过滤；`src/judge_laya.py` 读取本地多语言权重，使用 `choice` 判断意图和处理方式、用 `score` 估计风险；`src/reply_policy.py` 对 Laya 的结果施加确定性规则；`src/generate.py` 在需要时调用回复模型；`src/fill.py` 仅在用户点击填入后操作微信输入框。

判断会在 OCR 发现新消息后提前启动。结果若仍对应当前会话和消息，立即显示意图、风险、策略与 Laya 判断用时；显示完成后才继续等待消息停稳并决定是否调用生成模型。回复生成必须等待判断与策略完成，因此消息快速变化时不会为已过期的中间消息付费生成。候选始终按高情商、阴阳怪气、一本正经三类显示；本地模板直接提供三条，推理回复由一次模型请求写出三条。

聊天区左边界由输入框的视觉轮廓决定，同一个边界用于 OCR ROI、画面指纹、标题及消息提取。无会话列表的宽窗口中，短消息字框的归一化高度可能小于旧昵称阈值；该布局不启用旧版的孤立昵称过滤。输入区边界无法确认时仍暂停分析，以免把输入草稿当成对方消息。

风险达到 7/9 时程序提示用户自己处理。Laya 返回“暂不回复”时，只有低风险、意图为闲聊且处理判断把握度至少 0.5 才跳过；工作类消息继续生成。Laya 可能把“派活”误判成“催进度”，这些规则用于避免最明显的漏回，仍需要真实聊天样本校准。

截图、OCR、Laya 判断与候选排序均在本机运行。仅当策略选择生成且回复模型是云端服务时，聊天文字才离开电脑。开源发行版不提供共享密钥或免费中转；请配置自己的回复接口，或本地 Ollama。
